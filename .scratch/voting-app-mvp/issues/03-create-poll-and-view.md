# 03: 투표 만들기, 목록, 투표 페이지 보기

**What to build:** 관리자가 `/admin/new`에서 질문과 선택지 2~10개를 입력해 투표를 만든다. 새 투표는 곧바로 메인 목록과 관리 목록에 `진행 중` 뱃지와 함께 최신순으로 나타난다. 누구나 목록이나 공유 링크(`/polls/[id]`)로 들어와 질문과 선택지를 생성 순서대로 볼 수 있다. 투표 제출은 04에서 한다. 스펙: `.scratch/voting-app-mvp/spec.md`.

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 투표 모듈의 `createPoll({ question, options[] })`는 다음처럼 동작한다.
  - 입력의 앞뒤 공백을 제거한 뒤 검증한다: 질문 1~200자, 선택지 1~100자, 선택지 2~10개, 공백 제거 후 중복 금지.
  - 실패하면 필드별 검증 오류를 반환 값으로 돌려준다. 예외를 던지지 않는다.
  - 성공하면 URL-safe 10자 랜덤 ID를 돌려준다.
  - `polls`와 `options`를 한 트랜잭션 또는 한 문장으로 저장해서, 선택지 없는 투표가 남지 않는다.
- [ ] 투표 모듈의 `getPollForVoter(pollId, voterId | null)`는 질문, 순서대로 된 선택지, 상태를 반환하고, 없는 투표면 "없음"을 반환한다. 진행 중인 투표의 반환 값에는 수치 필드가 아예 없다.
- [ ] `/admin/new` 폼 동작:
  - 선택지 칸을 추가/제거할 수 있다 (2~10개).
  - 검증 오류는 해당 필드 옆에 한국어로 표시한다.
  - 실패해도 입력한 내용은 폼에 남는다.
  - 생성에 성공하면 관리 목록으로 이동한다.
- [ ] 투표 생성 Server Action은 첫 줄에서 관리자 세션을 검증하고, 실패하면 아무것도 만들지 않는다.
- [ ] 메인 목록과 관리 목록에 새 투표가 즉시 반영된다 (`revalidatePath`). 각 항목에는 `진행 중`/`마감` 뱃지가 붙고, 항목을 누르면 `/polls/[id]`로 이동한다.
- [ ] `/polls/[id]`는 질문과 선택지를 생성 순서대로 보여주고, 없는 ID면 "찾을 수 없음"(404)을 보여준다.
- [ ] 통합 테스트:
  - 검증 오류: 길이, 개수, 중복, 공백만 있는 입력
  - 정상 생성 후 `getPollForVoter`와 `listPolls`로 조회
  - 선택지 순서가 보존됨
  - 없는 ID 조회
