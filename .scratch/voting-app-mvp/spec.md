# 투표 앱 MVP

Status: ready-for-agent

## Problem Statement

동아리나 수업 같은 수십~수백 명 규모의 모임에서 질문 하나를 올리고, 사람들이 선택지 중 하나를 골라 투표한 뒤 결과를 확인할 간단한 방법이 필요하다. 기존 설문 도구는 가입이 필요하거나 기능이 과하다. 또 투표 도중에 결과가 보이면 사람들이 앞선 선택지를 따라 찍게 된다. 투표를 만들고 정리하는 사람(운영자)은 한 명이며, 복잡한 계정 관리 없이 비밀번호 하나로 관리하고 싶다.

## Solution

Vercel에 배포되고 Neon Postgres를 쓰는 한국어 웹앱을 만든다.

- 누구나 로그인 없이 메인 목록이나 공유 링크로 투표에 들어와 선택지 하나에 표를 던질 수 있다.
- 한 브라우저는 한 투표에 한 번만 투표할 수 있고, 투표한 뒤에는 자신의 선택만 보인다.
- 결과(선택지별 득표수와 비율)는 운영자가 투표를 마감한 뒤에만 모두에게 공개된다.
- 운영자는 환경변수로 정한 비밀번호로 로그인해 투표를 만들고, 마감하고, 삭제한다. 마감 전에도 득표 현황을 볼 수 있다.

용어는 `CONTEXT.md`를 따른다. 결정 배경은 `docs/adr/0001`~`0005`에 있다.

## User Stories

### 투표자: 찾기와 들어가기

1. As a 투표자, I want to 메인 페이지에서 투표 목록을 최신순으로 보고, so that 지금 어떤 투표가 있는지 알 수 있다
2. As a 투표자, I want to 목록의 각 투표에 `진행 중` / `마감` 뱃지가 붙어 있기를, so that 참여할 수 있는 투표와 결과를 볼 수 있는 투표를 구분할 수 있다
3. As a 투표자, I want to 목록에서 투표를 눌러 해당 투표 페이지로 이동하고, so that 투표하거나 결과를 볼 수 있다
4. As a 투표자, I want to 누군가 공유한 링크로 곧바로 투표 페이지에 들어가고, so that 목록을 뒤지지 않아도 된다
5. As a 투표자, I want to 로그인이나 가입 없이 투표하고, so that 부담 없이 바로 참여할 수 있다
6. As a 투표자, I want to 존재하지 않거나 삭제된 투표 링크에 들어가면 "찾을 수 없음" 화면을 보고, so that 링크가 잘못됐다는 것을 알 수 있다
7. As a 투표자, I want to 투표가 하나도 없을 때 빈 목록 안내를 보고, so that 앱이 고장 난 것이 아님을 알 수 있다

### 투표자: 표 던지기

8. As a 투표자, I want to 진행 중인 투표에서 질문과 선택지를 생성된 순서대로 보고, so that 무엇에 대한 투표인지 이해할 수 있다
9. As a 투표자, I want to 선택지 중 정확히 하나를 골라 제출하고, so that 내 의견을 표로 남길 수 있다
10. As a 투표자, I want to 제출 후 "투표 완료, 당신의 선택: ○○" 화면을 보고, so that 내 표가 제대로 들어갔는지 확인할 수 있다
11. As a 투표자, I want to 같은 투표에 다시 들어왔을 때도 내 선택이 표시되기를, so that 이미 투표했다는 것을 기억하지 않아도 된다
12. As a 투표자, I want to 이미 투표한 투표에서는 다시 제출할 수 없기를, so that 한 사람의 표가 여러 번 집계되지 않는다

## Implementation Decisions

### 모듈 구성

**투표 모듈 (Poll module):** 투표 도메인 전체를 담는 깊은 모듈이다.
- DB 핸들을 인자로 받고, 쿠키, 요청, Next API는 전혀 모른다.
- 투표자 식별자(`voterId`)도 호출자가 넘긴다.
- 인터페이스:
  - `listPolls()`: 모든 투표를 최신순으로 반환한다. 각 항목은 ID, 질문, 진행 중/마감 여부, 생성 시각을 가진다.
  - `getPollForVoter(pollId, voterId | null)`: 투표자 시점의 화면 모델을 반환한다. 모델에는 질문, 순서대로 된 선택지, 상태, 내 선택(있으면)이 들어간다. 결과(선택지별 득표수, 비율, 최다 득표 여부, 총 표 수)는 마감된 투표일 때만 들어간다. 진행 중이면 어떤 수치도 들어가지 않는다. 투표가 없으면 "없음"을 반환한다.
  - `castVote(pollId, optionId, voterId)`: 성공하거나, 구분된 실패 사유를 돌려준다. 사유는 `투표 없음`, `마감됨`, `이미 투표함`, `잘못된 선택지` 중 하나다. 이 사유들은 예외가 아니라 결과 값이다.
  - `createPoll({ question, options[] })`: 입력을 정규화(앞뒤 공백 제거)하고 검증한다. 성공하면 새 투표 ID를 돌려주고, 실패하면 필드별 검증 오류를 돌려준다.
  - `closePoll(pollId)`: 멱등이다. 이미 마감됐어도 성공으로 본다. 투표가 없으면 `투표 없음`을 돌려준다.
  - `deletePoll(pollId)`: 멱등이다. 없어도 성공으로 본다.
  - `getPollForAdmin(pollId)` 및 관리 목록: 마감 여부와 관계없이 득표 현황을 포함한다.
- 결과 계산(비율 반올림, 최다 득표와 동점 판정, 0표 처리)과 입력 검증은 이 모듈 내부의 순수 함수로 둔다.

**운영자 인증 모듈 (Admin auth module):**
- `verifyAdminPassword(input)`: 타이밍 공격에 안전한 비교를 하고, 실패하면 약 1초 지연한다.
- `createAdminSession()`: `jose`로 서명한 토큰을 만든다. 서명 키는 `SESSION_SECRET`, 만료는 7일이다.
- `verifyAdminSession(token)`: 서명과 만료를 검증한다.
- 쿠키 입출력은 이 모듈 밖(얇은 어댑터)에서 한다.

**얇은 어댑터:**
- **Server Action:** 쿠키를 읽고 쓴 뒤 위 두 모듈을 호출하고 `revalidatePath`를 부른다.
  - 투표 제출 액션은 `voter_id` 쿠키가 없으면 새 UUID를 발급한다(httpOnly, `SameSite=Lax`, 1년).
  - 모든 운영자 액션은 첫 줄에서 세션을 검증하고, 실패하면 아무 작업도 하지 않는다. Next 16에서 Server Action은 공개 엔드포인트이기 때문이다 (ADR-0004).
- **페이지:** 모두 요청마다 렌더링하는 동적 페이지다. `cacheComponents`는 쓰지 않는다.
- **proxy:** 세션 쿠키가 없거나 유효하지 않으면 관리 경로에서 로그인 페이지로 리다이렉트한다. 편의 기능일 뿐, 보안 경계가 아니다.

**DB 접근:**
- ORM 없이 `@neondatabase/serverless`의 `sql` 태그 템플릿을 쓴다 (ADR-0003).
- 쿼리는 투표 모듈 안에 모으고, 결과 행 타입은 직접 선언한다.
- 값은 항상 파라미터로 넘긴다.

**마이그레이션:**
- 번호가 붙은 SQL 파일을 둔다.
- 작은 러너 스크립트(npm 스크립트 `db:migrate`)가 대상 URL에 미적용 파일만 순서대로 적용하고, `schema_migrations` 테이블에 기록한다.

### 스키마

- **`polls`:**
  - `id`: 텍스트 PK, URL-safe 10자 랜덤 ID
  - `question`: 텍스트
  - `closed_at`: nullable timestamptz. NULL이면 진행 중이다 (ADR-0002).
  - `created_at`
- **`options`:**
  - `id`: bigserial PK
  - `poll_id`: `polls` 참조, `ON DELETE CASCADE`
  - `label`
  - `position`: 0부터
  - 유니크 `(poll_id, position)`
  - 유니크 `(poll_id, id)`: 복합 FK의 참조 대상
- **`votes`:**
  - 컬럼: `poll_id`, `option_id`, `voter_id`(uuid), `created_at`
  - PK `(poll_id, voter_id)`
  - `(poll_id, option_id)` → `options(poll_id, id)` 복합 FK, `ON DELETE CASCADE`
- 목록 정렬용 인덱스로 `polls(created_at desc)`를 둔다.

### 무결성 (ADR-0005)

- 표 삽입은 해당 투표가 존재하고 `closed_at IS NULL`일 때만 행을 만드는 `INSERT ... SELECT` 한 문장으로 한다.
- 행이 삽입되지 않았거나 제약 위반이 나면, 원인을 판별해 구분된 실패 사유로 바꾼다.
  - PK 위반 → `이미 투표함`
  - FK 위반 → `잘못된 선택지`
  - 삽입 0행 → 투표가 있으면 `마감됨`, 없으면 `투표 없음`
- 투표 생성은 `polls`와 `options`를 한 트랜잭션 또는 한 문장으로 넣는다. 선택지 없는 투표가 남지 않게 하기 위해서다.

### 기타

- UI는 한국어만 지원한다. Tailwind v4를 쓴다.
- 폼 상태와 오류 표시는 `useActionState`로 한다 (`useFormState`는 deprecated).
- 환경변수는 `DATABASE_URL`, `TEST_DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`이다. 필수 값이 없으면 사용하는 시점에 명확한 오류로 실패한다.

## Testing Decisions

- **좋은 테스트의 기준:** 모듈의 공개 인터페이스만 호출하고, 관찰 가능한 결과(반환 값, 이후 조회 결과)만 확인한다. SQL 문장, 내부 함수, 테이블 구조를 직접 검사하지 않는다. 그래서 내부 구현을 바꿔도 동작이 같으면 테스트는 그대로 통과해야 한다.
- **도구:** 테스트 러너는 Vitest다. 새로 설치하고 `test` npm 스크립트를 추가한다.
- **투표 모듈 통합 테스트:**
  - 대상 DB: Neon `test` 브랜치(`TEST_DATABASE_URL`)
  - 준비와 초기화: 테스트 시작 전 마이그레이션 러너로 스키마를 적용하고, 각 테스트 전에 테이블을 `TRUNCATE`한다.
  - 실행 방식: 파일을 병렬로 돌리지 않고 순차 실행한다. 로컬에서만 실행한다.
  - 검증할 동작:
    - 생성: 입력 검증 오류(길이, 개수, 중복, 공백), 정상 생성 후 조회
    - 목록: 최신순 정렬
    - 투표: 정상 투표 후 내 선택 조회, 같은 투표자의 두 번째 표 거부, 다른 투표의 선택지 거부, 마감 후 투표 거부, 없는 투표에 투표 거부, 같은 투표자가 다른 투표에는 투표 가능
    - 결과 공개: 진행 중일 때 투표자 시점에 수치가 전혀 없음, 운영자 시점에는 항상 득표 현황이 있음
    - 결과 계산: 비율 반올림, 동점일 때 모두 최다 득표 표시, 0표 결과
    - 마감과 삭제: 마감과 삭제의 멱등성, 삭제 후 선택지와 표까지 사라지고 조회 시 "없음"
- **운영자 인증 모듈 단위 테스트 (DB 없음):**
  - 비밀번호: 맞는 비밀번호, 틀린 비밀번호, 길이가 다른 입력
  - 세션: 새로 만든 세션 검증 성공, 만료된 토큰 거부, 변조된 토큰 거부, 다른 키로 서명된 토큰 거부
  - 실패 지연 때문에 테스트가 느려지지 않도록, 지연은 주입하거나 가짜 타이머로 처리한다.
- **테스트하지 않는 것:** Server Action, 페이지, proxy는 자동 테스트하지 않는다. "모든 운영자 액션이 세션을 검증하는가"는 테스트로 잡히지 않으므로 코드 리뷰 체크 항목으로 둔다.
- **기존 테스트:** 저장소에 아직 테스트가 없다. 이 작업이 첫 기준 사례가 된다.

## Out of Scope

- 투표자 로그인이나 소셜 로그인, IP 기반 중복 방지, 봇 방지(CAPTCHA)
- 표 변경 또는 취소
- 투표(질문, 선택지) 수정
- 마감 재개, 마감 일시를 미리 지정하는 자동 마감
- 복수 선택, 순위 투표, 이미지 선택지
- 여러 운영자 계정, 운영자 추가 기능, 서버 측 개별 세션 강제 종료
- IP별 로그인 시도 제한
- 소프트 삭제, 삭제 복구, 감사 로그
- 실시간 결과 갱신(폴링, WebSocket, SSE)
- 목록 페이지네이션, 검색
- 다국어 지원
- Playwright E2E 테스트, CI 테스트 실행, Preview 배포별 Neon 브랜치

## Further Notes

- 이 프로젝트의 Next.js는 16.3.6이다. 구현 전에 `node_modules/next/dist/docs/`의 관련 문서를 확인할 것 (AGENTS.md). 주요 변경은 다음과 같다.
  - `cookies()`는 async로만 쓸 수 있다.
  - `middleware`는 `proxy`로 바뀌었다.
  - `revalidateTag`는 두 번째 인자가 필수다.
  - Edge runtime은 deprecated다.
- `voter_id`는 사람이 아니라 브라우저 하나를 식별한다. 쿠키를 지우거나 시크릿 창을 쓰면 다시 투표할 수 있다. 이는 알고 수용한 한계다 (ADR-0001).
- 투표자는 마감 전에 결과를 볼 수 없다. 이 규칙은 UI가 아니라 투표 모듈의 반환 값 수준에서 강제한다. 진행 중인 투표에 대한 투표자 시점 모델에는 수치 필드 자체가 없어야 한다.
- 이후 필요해지면 추가를 검토할 것: 폴링 기반 결과 갱신, 목록 페이지네이션, CI 테스트.
