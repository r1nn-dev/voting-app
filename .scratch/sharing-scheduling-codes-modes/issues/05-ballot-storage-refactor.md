# 05: 표 저장 구조 전환 (사전 정리, 동작 변화 없음)

**What to build:** 투표자와 관리자가 보기에 바뀌는 것은 없다. 표를 "표 한 행 + 고른 선택지 행"으로 저장하도록 바꾼다(ADR-0008). 지금 표의 기본 키 `(투표, 투표자 ID)`는 참여 코드(한 브라우저로 여러 표, 06)와 복수 선택(한 표에 선택지 여러 개, 07)을 둘 다 막는다. 저장 구조를 한 번만 바꿔 두어, 06과 07이 각자 마이그레이션을 하지 않게 한다. 이 티켓에서는 여전히 단일 선택과 브라우저당 한 표만 받는다. 스펙: `.scratch/sharing-scheduling-codes-modes/spec.md`. 결정 배경: ADR-0005, ADR-0007, ADR-0008.

**Blocked by:** None (can start immediately). 04와 동시에 진행하면 `castVote`에서 병합 충돌을 한 번 정리해야 할 수 있다.

**Status:** ready-for-agent

- [ ] 새 마이그레이션이 두 테이블을 만든다.
  - **표:** ID, 투표, 투표자 ID, 코드 투표 여부(기본 false), 던진 시각
  - **고른 선택지:** 표, 투표, 선택지
  - 제약:
    - 선택지는 (투표, 선택지) 복합 FK로 다른 투표의 선택지를 막는다.
    - (표, 선택지) 유일로 한 표 안의 중복 선택지를 막는다.
    - 브라우저당 한 표는 "코드 투표가 아닌 표"에만 거는 (투표, 투표자 ID) 부분 유니크 인덱스로 보장한다.
    - 투표를 삭제하면 표와 고른 선택지가 cascade로 사라진다.
- [ ] 같은 마이그레이션이 기존 표를 새 구조로 옮기고 옛 표 테이블을 없앤다. 옮기기 전후의 선택지별 표 수가 같다.
- [ ] `castVote(pollId, optionIds[], voterId)`는 선택지 배열을 받는다.
  - 표 행과 고른 선택지 행을 한 문장(CTE)으로 저장한다. 진행 중 확인(판정식), 표 삽입, 선택지 삽입이 함께 성공하거나 함께 실패한다.
  - 단일 선택이라 선택지는 정확히 1개여야 한다. 0개, 2개 이상, 형식 오류, 다른 투표의 선택지는 `invalid_choice`로 거부한다(기존 `invalid_option`을 대체).
  - 나머지 실패 사유(`not_found`/`closed`/`already_voted`, 04가 먼저 끝났다면 `not_started`)는 그대로다.
- [ ] 투표자 조회의 내 선택은 `myChoices`(선택지 ID 배열)로 바꾼다. 집계(결과, 득표 현황, 순위와 격차, CSV)는 새 구조에서 같은 값을 낸다.
- [ ] 투표 폼과 투표 Server Action이 새 인터페이스(선택지 배열, `myChoices`)를 쓴다. 화면과 안내 문구는 바뀌지 않는다.
- [ ] 시드 스크립트가 새 구조로 표를 넣는다.
- [ ] 기존 통합 테스트를 새 인터페이스로 바꾸고, 모두 통과한다. 추가로 다음을 검증한다.
  - 선택지 0개와 2개가 `invalid_choice`로 거부된다.
  - 같은 브라우저의 두 번째 표가 여전히 `already_voted`다.
- [ ] `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.
