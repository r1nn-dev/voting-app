# 04: 예약 공개 (시작 예정 시각과 시작 전 상태)

**What to build:** 관리자가 투표를 만들 때 **시작 예정 시각**을 정하거나 비워 둔다(비우면 바로 시작). 그 시각 전까지 투표는 **시작 전**이다. 질문과 선택지는 보이지만 표를 받지 않고, 투표 페이지는 "○월 ○일 오후 3:00에 시작합니다"를 보여준다. 메인 목록에는 "시작 예정" 구역(시작이 가까운 순, "N시간 후 시작")이, 관리 화면에는 "시작 전" 탭이 생긴다. 시작 전인 투표는 관리자가 시작·마감 예정 시각을 자유롭게 바꾸거나 "지금 바로 시작"할 수 있고, 마감 대신 삭제만 할 수 있다. 스펙: `.scratch/sharing-scheduling-codes-modes/spec.md`. 결정 배경: ADR-0006(갱신).

**Blocked by:** None (can start immediately). 1단계(01~03) 배포 뒤에 시작하길 권한다. 05와 동시에 진행하면 `castVote`와 판정식에서 병합 충돌을 한 번 정리해야 할 수 있다.

**Status:** ready-for-agent

- [ ] 새 마이그레이션이 `polls.opens_at`(NOT NULL)을 추가하고, 기존 투표는 `created_at`으로 채운다.
- [ ] 판정식에 `scheduled`를 추가한다: 시작 예정 시각 > 지금. 기존 판정식과 같은 곳에서 정의하고 한 호출에 시계를 한 번만 읽는다. 상태는 `scheduled` → `open` → `closed` → `archived` 순서다.
- [ ] `createPoll`이 `opensAt`(선택, 없으면 지금)을 받는다. 범위 검사는 삽입 문장 안에서 같은 시계로 한다.
  - 시작 예정 시각: 지금 ~ 지금 + 30일
  - 마감 예정 시각: 시작 예정 시각 + 10분 ~ + 30일
- [ ] `castVote`는 시작 전 투표를 `not_started`로 거부한다(조건부 INSERT 안에서). `closePoll`도 시작 전 투표를 `not_started`로 거부한다. `extendDeadline`은 지금처럼 진행 중만 허용한다.
- [ ] 투표 모듈의 `reschedule(pollId, { opensAt, deadline })`는 시작 전일 때만 한 문장 조건부 UPDATE로 동작한다. 범위는 생성과 같다. 실패 사유는 `not_found` / `started` / `out_of_range`. "지금 바로 시작"은 `opensAt = 지금`이다.
- [ ] 투표자 조회에 `scheduled` 상태를 추가한다. 질문, 선택지, 시작 예정 시각, 마감 예정 시각을 담고, 수치는 없다.
- [ ] `listPolls`(메인)에 `scheduled` 구역(시작 예정 시각 오름차순, 링크 전용 제외)을 추가한다. `listPollsForAdmin`에 `scheduled` 묶음을 추가한다.
- [ ] 화면:
  - 새 투표 폼에 시작 예정 시각(선택, "바로 시작" 기본)을 둔다.
  - 메인 구역 순서는 진행 중 → 시작 예정 → 마감된 투표다.
  - 관리 탭은 시작 전 / 진행 중 / 마감 / 보관이고, 기본 탭은 진행 중이다.
  - 투표 페이지의 시작 전 안내에서는 선택지를 보여주되 선택은 막는다.
  - 관리자 상세(시작 전): 시작·마감 예정 시각 변경, "지금 바로 시작", 삭제. 마감 버튼과 연장 영역은 없다.
  - 상태 뱃지에 "시작 전"을 추가한다.
- [ ] 새 관리자 Server Action(시각 변경, 지금 바로 시작)은 첫 줄에서 세션을 검증하고, 관련 페이지를 갱신한다. 투표 ID는 숨은 입력값으로 보낸다.
- [ ] 시드에 시작 전 예시 1개를 추가한다. 도움말에 시작 전 투표 안내를 추가한다.
- [ ] 통합 테스트(시계 주입):
  - 상태 경계: 시작 1초 전은 `scheduled`, 시작 순간은 `open`
  - 시작 전 `castVote`와 `closePoll`의 `not_started`
  - 투표자 시점에 수치 없음
  - 생성 범위(시작 30일 초과, 마감이 시작 + 10분 미만·+ 30일 초과 거부)
  - `reschedule` 성공과 `started`/`out_of_range`/`not_found`, 지금 바로 시작
  - 메인 시작 예정 구역의 정렬과 링크 전용 제외, 관리 목록의 `scheduled` 묶음
- [ ] `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.
