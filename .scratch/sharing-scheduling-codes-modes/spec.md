# 공유, 링크 전용, 관리자 편의, 예약 공개, 참여 코드, 투표 모드

Status: ready-for-agent

## Problem Statement

투표는 링크로 퍼지는데, 지금은 링크를 주소창에서 직접 복사해야 하고, 교실이나 모임에서 화면에 띄워 바로 참여를 받을 방법이 없다. 모든 투표가 메인 목록에 나오기 때문에, 특정 모임만 쓰는 투표도 모두에게 노출된다. 관리자는 결과를 문서로 옮기려면 화면을 보고 받아 적어야 하고, 매주 비슷한 투표를 처음부터 다시 만들어야 한다. 투표는 만드는 즉시 시작되므로 "월요일 9시에 시작"처럼 미리 준비해 둘 수 없다. 브라우저당 한 표는 시크릿 창이나 쿠키 삭제로 우회할 수 있어, 공정성이 중요한 투표에는 부족하다. 그리고 선택지를 하나만 고를 수 있어서 "가능한 날짜를 모두 고르세요" 같은 질문을 할 수 없다.

## Solution

- **공유:** 투표 페이지와 관리자 상세 화면에 "링크 복사" 버튼과 QR 코드를 둔다. 관리자는 질문과 QR만 크게 보여주는 전체 화면(프로젝터용)을 띄울 수 있다.
- **링크 전용:** 투표를 **목록 공개** 또는 **링크 전용**으로 만들 수 있고, 관리자가 언제든 바꿀 수 있다. 링크 전용 투표는 메인 목록에 나오지 않고, 링크를 가진 사람만 들어온다.
- **관리자 편의:** 투표 결과(마감 전에는 득표 현황)를 CSV로 받을 수 있다. 기존 투표를 복제하면 새 투표 폼이 같은 설정으로 미리 채워져 열린다.
- **예약 공개:** 투표를 만들 때 **시작 예정 시각**을 정할 수 있다. 그 전까지 투표는 **시작 전**이다. 질문과 선택지는 보이지만 표를 받지 않는다. 상태는 시작 전 → 진행 중 → 마감 → 보관 순서로만 바뀐다.
- **참여 코드:** 투표마다 **참여 코드**를 켤 수 있다. 관리자가 1회용 코드를 발급해 한 사람에게 하나씩 나눠 주고, 코드 하나로 표를 한 번만 던질 수 있다. 어떤 코드로 어떤 표를 던졌는지는 남기지 않는다.
- **투표 모드:** 투표를 만들 때 **단일 선택** 또는 **복수 선택**(최대 선택 수 지정)을 고른다. 복수 선택의 결과는 선택지별로 "표 중 몇 %가 골랐나"를 보여준다.
- **조합:** 모든 설정은 서로 독립적이라 함께 켤 수 있다.

용어는 `CONTEXT.md`를 따른다: 표, 결과, 투표 모드, 단일 선택, 복수 선택, 최대 선택 수, 목록 공개, 링크 전용, 참여 코드, 시작 예정 시각, 시작 전, 진행 중, 마감, 보관. 결정 배경은 `docs/adr/0007`(참여 코드), `docs/adr/0008`(복수 선택의 표), 갱신된 `0006`(시작 전 판정), `0001`, `0005`에 있다.

## User Stories

### 투표자: 공유

1. As a 투표자, I want to 투표 페이지에서 "링크 복사"를 눌러 주소를 복사하고, so that 친구에게 쉽게 전달한다
2. As a 투표자, I want to 복사가 되면 "복사됨" 안내를 보고, so that 제대로 복사됐는지 안다
3. As a 투표자, I want to 투표 페이지에서 QR 코드를 펼쳐 보고, so that 옆 사람이 휴대폰 카메라로 바로 들어오게 한다
4. As a 투표자, I want to 공유된 주소가 운영 사이트 주소이기를, so that 받은 사람이 엉뚱한 미리보기 사이트로 가지 않는다
5. As a 투표자, I want to 공개 기간이 끝난 투표에는 공유 버튼이 보이지 않기를, so that 볼 수 없는 링크를 퍼뜨리지 않는다

### 관리자: 공유

6. As a 관리자, I want to 상세 화면에서 링크 복사와 QR을 쓰고, so that 투표를 만든 직후 바로 공유한다
7. As a 관리자, I want to "QR 크게 보기"로 질문과 QR만 화면 가득 띄우고, so that 수업이나 모임에서 프로젝터로 참여를 받는다
8. As a 관리자, I want to 전체 화면 QR에 남은 시간이나 시작 시각이 함께 보이기를, so that 참여자에게 언제까지인지 알린다

### 링크 전용

9. As a 관리자, I want to 투표를 만들 때 목록 공개 또는 링크 전용을 고르고, so that 특정 모임만 쓰는 투표를 목록에 노출하지 않는다
10. As a 관리자, I want to 상세 화면에서 목록 공개와 링크 전용을 언제든 바꾸고, so that "링크로 모은 뒤 결과는 목록에 공개"처럼 쓸 수 있다
11. As a 관리자, I want to 관리 목록과 상세 화면에서 "링크 전용" 뱃지를 보고, so that 어떤 투표가 목록에 안 나오는지 안다
12. As a 투표자, I want to 링크 전용 투표도 링크로는 평소처럼 투표하고 결과를 보고, so that 목록에 없다는 것 말고는 차이가 없다
13. As a 투표자, I want to 링크 전용 투표가 마감되거나 보관돼도 메인 목록에 나오지 않기를, so that 모임 밖으로 결과가 노출되지 않는다

### 관리자: CSV와 복제

14. As a 관리자, I want to 상세 화면에서 결과 CSV를 받고, so that 결과를 보고서나 스프레드시트로 옮긴다
15. As a 관리자, I want to CSV에 투표 정보(질문, 상태, 투표 모드, 시작·마감 시각, 총 표 수)와 선택지별 표 수, 비율, 순위가 담기기를, so that 따로 계산하지 않아도 된다
16. As a 관리자, I want to 마감 전에도 CSV를 받고, so that 진행 중에 득표 현황을 공유한다
17. As a 관리자, I want to CSV를 엑셀에서 열어도 한글이 깨지지 않기를, so that 바로 쓸 수 있다
18. As a 관리자, I want to CSV에 투표자를 알아볼 수 있는 값이 없기를, so that 익명성이 지켜진다
19. As a 관리자, I want to "복제"를 누르면 새 투표 폼이 질문, 선택지, 투표 모드, 최대 선택 수, 공개 방식, 참여 코드 사용 여부로 채워져 열리기를, so that 비슷한 투표를 빠르게 다시 만든다
20. As a 관리자, I want to 복제 폼에서 시각은 새로 정하게 되기를, so that 지난 투표의 시각을 실수로 그대로 쓰지 않는다
21. As a 관리자, I want to 복제해도 표와 참여 코드는 따라오지 않기를, so that 새 투표가 깨끗하게 시작한다

### 예약 공개

22. As a 관리자, I want to 투표를 만들 때 시작 예정 시각을 정하거나 비워 두고, so that 미리 만들어 두거나 바로 시작한다
23. As a 관리자, I want to 시작 예정 시각은 지금부터 30일 이내로만 정할 수 있기를, so that 너무 먼 투표가 쌓이지 않는다
24. As a 관리자, I want to 마감 예정 시각이 시작 예정 시각 기준으로 10분~30일 사이여야 하기를, so that 투표 기간이 너무 짧거나 길지 않다
25. As a 관리자, I want to 시작 전인 투표의 시작 예정 시각과 마감 예정 시각을 자유롭게 바꾸고, so that 일정 변경에 맞춘다
26. As a 관리자, I want to 시작 전인 투표를 "지금 바로 시작"하고, so that 준비가 끝나면 기다리지 않아도 된다
27. As a 관리자, I want to 시작 전인 투표에는 마감 버튼 대신 삭제만 있기를, so that 0표짜리 마감 투표가 생기지 않는다
28. As a 관리자, I want to 관리 화면에 "시작 전" 탭이 있고 시작이 가까운 순으로 정렬되기를, so that 준비 중인 투표를 한곳에서 본다
29. As a 투표자, I want to 메인 목록의 "시작 예정" 구역에서 곧 시작할 투표와 "N시간 후 시작"을 보고, so that 미리 알고 기다린다
30. As a 투표자, I want to 시작 전 투표 페이지에서 질문과 선택지를 미리 보되 선택은 못 하고, "○월 ○일 오후 3:00에 시작합니다"를 보고, so that 언제 다시 오면 되는지 안다
31. As a 투표자, I want to 시작 시각이 되는 순간부터 투표할 수 있기를, so that 따로 공지를 기다리지 않는다
32. As a 투표자, I want to 시작 전에 제출을 시도하면 "아직 시작하지 않은 투표입니다" 안내를 받고, so that 표가 반영되지 않았다는 것을 안다

### 참여 코드

33. As a 관리자, I want to 투표를 만들 때 참여 코드를 켜고 발급할 개수(1~500)를 정하고, so that 코드를 받은 사람만 한 번씩 투표한다
34. As a 관리자, I want to 진행 중이거나 시작 전인 투표에 코드를 추가로 발급하고, so that 참여자가 늘어나도 대응한다
35. As a 관리자, I want to 상세 화면에서 "코드 N개 중 M개 사용"을 보고, so that 참여 정도를 안다
36. As a 관리자, I want to 코드 목록을 CSV로 받고, so that 인쇄하거나 메시지로 나눠 준다
37. As a 관리자, I want to 코드 목록 CSV에 사람마다 쓸 개인 링크(`?code=` 포함)가 함께 담기기를, so that 코드를 따로 안내하지 않아도 된다
38. As a 관리자, I want to 코드가 헷갈리는 글자 없이 8자리이기를, so that 손으로 옮겨 적어도 틀리지 않는다
39. As a 관리자, I want to 어떤 코드로 어떤 선택을 했는지 알 수 없기를, so that 코드를 나눠 준 사람의 선택도 익명으로 남는다
40. As a 투표자, I want to 코드 투표 페이지에서 참여 코드 입력칸을 보고, so that 받은 코드를 넣고 투표한다
41. As a 투표자, I want to 개인 링크로 들어오면 코드가 이미 채워져 있기를, so that 타이핑하지 않아도 된다
42. As a 투표자, I want to 코드를 소문자나 공백을 섞어 넣어도 받아들여지기를, so that 입력 실수로 막히지 않는다
43. As a 투표자, I want to 틀렸거나 이미 쓴 코드면 "사용할 수 없는 코드입니다" 안내를 받고, so that 다시 확인한다
44. As a 투표자, I want to 한 기기로 여러 사람이 각자 코드를 넣고 투표할 수 있기를, so that 교실 태블릿 한 대로도 투표를 받는다
45. As a 투표자, I want to 투표 완료 화면에서 "다른 코드로 투표하기"를 누르고, so that 다음 사람이 이어서 투표한다
46. As a 투표자, I want to 코드가 필요 없는 투표는 지금처럼 브라우저당 한 표이기를, so that 가벼운 투표는 코드 없이 쓴다

### 투표 모드

47. As a 관리자, I want to 투표를 만들 때 단일 선택 또는 복수 선택을 고르고, so that 질문에 맞는 방식으로 묻는다
48. As a 관리자, I want to 복수 선택이면 최대 선택 수(2~선택지 개수, 기본은 전부)를 정하고, so that "최대 3개까지"처럼 제한한다
49. As a 관리자, I want to 투표 모드와 최대 선택 수는 만든 뒤 바꿀 수 없기를, so that 이미 들어온 표의 의미가 달라지지 않는다
50. As a 투표자, I want to 복수 선택 투표에서 체크박스로 여러 개를 고르고 "최대 N개 · 지금 M개 선택"을 보고, so that 몇 개 더 고를 수 있는지 안다
51. As a 투표자, I want to 최대 개수를 다 고르면 나머지 선택지가 비활성화되기를, so that 초과해서 고르지 않는다
52. As a 투표자, I want to 하나도 고르지 않으면 제출할 수 없기를, so that 빈 표를 던지지 않는다
53. As a 투표자, I want to 투표 완료 화면에서 "당신의 선택: 김밥, 라면"처럼 고른 것을 모두 보고, so that 제대로 들어갔는지 확인한다
54. As a 투표자, I want to 복수 선택 결과를 선택지별 가로 막대와 "표 중 N%"로 보고, so that 몇 명이 그 선택지를 골랐는지 안다
55. As a 투표자, I want to 복수 선택 결과의 비율 합이 100%를 넘는다는 안내를 보고, so that 오류로 오해하지 않는다
56. As a 투표자, I want to 복수 선택 결과에서도 1위와 내 선택이 표시되기를, so that 단일 선택과 같은 방식으로 읽는다
57. As a 관리자, I want to 복수 선택 투표의 순위와 격차도 표 대비 %p로 보고, so that 단일 선택과 같은 방식으로 분석한다

### 운영과 데이터

58. As a 개발자, I want to 마이그레이션이 기존 투표를 단일 선택, 목록 공개, 참여 코드 없음, 시작 예정 시각 = 만든 시각으로 채우고, 기존 표를 새 저장 구조로 옮기기를, so that 배포 후에도 모든 투표가 전과 똑같이 동작한다
59. As a 개발자, I want to 시드에 링크 전용, 복수 선택, 시작 전, 코드 투표 예시가 하나씩 들어가기를, so that 로컬에서 새 기능을 바로 확인한다
60. As a 개발자, I want to 운영 주소를 `SITE_URL` 환경변수로 정하고, 없으면 요청 도메인을 쓰기를, so that QR과 링크 복사가 운영 주소를 가리킨다
61. As a 투표자, I want to 도움말과 이용약관에 새 기능이 투표자 관점으로만 설명되기를(관리 기능 설명 없음), so that 필요한 것만 안다

## Implementation Decisions

### 단계

- **1단계:** 공유 · QR, 링크 전용, CSV, 복제. 기존 설계를 바꾸지 않는다.
- **2단계:** 예약 공개, 참여 코드. 상태와 무결성 규칙이 바뀐다.
- **3단계:** 투표 모드. 표 저장 구조와 결과 정의가 바뀐다.
- 티켓은 단계 순서로 나누고, 각 단계가 끝나면 배포할 수 있게 한다.

### 판정 규칙 (ADR-0006 갱신)

- 판정식은 투표 모듈 한 곳에만 두고, 한 호출에서 시계를 한 번만 읽는다(기존 원칙 유지).
- **시작 전:** 시작 예정 시각 > 지금. 표를 받지 않는다.
- **진행 중:** 시작했고 마감되지 않았다.
- **마감, 보관:** 기존 식을 그대로 쓴다.
- 상태 값은 `scheduled` / `open` / `closed` / `archived`이다.

### 스키마

- **`polls`에 추가:**
  - `opens_at` (NOT NULL). 기존 투표는 `created_at`으로 채운다.
  - `listed` (boolean, 기본 true)
  - `mode` (`single` | `multiple`, 기본 `single`)
  - `max_choices` (복수 선택일 때만. 2 이상, 선택지 개수 이하)
  - `uses_codes` (boolean, 기본 false)
- **표 저장 구조 변경 (ADR-0008):**
  - **표 한 행:** 투표, 투표자 ID, 코드 투표 여부, 던진 시각
  - **고른 선택지 행들:** 표, 선택지. 투표와 선택지의 복합 FK로 다른 투표의 선택지를 막고, 표 안에서 같은 선택지 중복을 막는다.
  - **브라우저당 한 표:** "코드 투표가 아닌 표"에 한정된 (투표, 투표자 ID) 유니크 제약으로 보장한다. 코드 투표의 표에는 적용하지 않는다(ADR-0007).
  - **기존 데이터:** 마이그레이션이 기존 표를 새 구조로 옮기고 옛 테이블을 없앤다. 삭제는 cascade를 유지한다.
- **참여 코드 테이블:** (투표, 코드) 유일, 사용 시각(NULL이면 미사용). 표와 연결하는 열은 두지 않는다.

### 투표 모듈 인터페이스

- **`createPoll`:** 입력에 다음을 더한다.
  - `opensAt`(선택. 없으면 지금), `mode`, `maxChoices`(복수 선택일 때), `listed`, `codeCount`(0이면 코드를 쓰지 않음, 1~500)
  - 범위 검사: 시작 예정 시각은 지금~지금 + 30일, 마감 예정 시각은 시작 예정 시각 + 10분~+ 30일. 삽입 문장 안에서 같은 시계로 검사한다.
  - 코드는 같은 문장이나 같은 트랜잭션 안에서 발급한다.
- **`castVote(pollId, optionIds[], voterId, code?)`:**
  - 실패 사유: `not_found` / `not_started` / `closed` / `already_voted` / `invalid_choice`(선택지 0개, 최대 선택 수 초과, 단일 선택인데 2개 이상, 다른 투표의 선택지, 형식 오류) / `invalid_code`(없음, 이미 사용, 다른 투표의 코드, 코드 투표인데 코드 없음을 모두 하나로)
  - 저장은 한 문장(CTE)으로 한다. 진행 중 확인, 코드 사용 처리(코드 투표일 때), 표 행과 선택지 행 삽입이 함께 성공하거나 함께 실패한다.
  - 코드는 앞뒤 공백과 대소문자를 정규화한다.
- **`getPollForVoter`:**
  - 상태 유니언에 `scheduled`를 추가한다. 질문, 선택지, 시작 예정 시각, 마감 예정 시각, 모드, 최대 선택 수, 코드 필요 여부를 담고, 수치는 없다.
  - `open`과 `closed`에 모드, 최대 선택 수, 코드 필요 여부를 더한다.
  - 내 선택은 `myChoices`(선택지 ID 배열)로 바꾼다. 코드 투표에서는 그 브라우저의 마지막 표 기준이다.
  - `archived`는 지금처럼 ID와 상태만이다.
- **결과 계산:**
  - 단일 선택: 지금의 비중(합 100%)을 유지한다.
  - 복수 선택: 선택지별 "그 선택지를 담은 표 수 ÷ 전체 표 수"를 쓴다. 합이 100%를 넘는다.
  - 1위(동점 포함)와 내 선택 표시는 두 모드에 공통이다.
- **`getPollForAdmin`:**
  - 더하는 것: 모드, 최대 선택 수, 공개 방식, 시작 예정 시각, 코드 통계(발급 수, 사용 수), 복제용 설정(질문, 선택지 순서, 모드, 최대 선택 수, 공개 방식, 코드 사용 여부)
  - 순위와 격차는 표 대비 비율로 계산한다(단일 선택에서는 지금과 같은 값).
- **`listPolls` (메인):** `scheduled`(시작이 가까운 순), `open`, `closed` 세 구역. 링크 전용과 보관은 제외한다.
- **`listPollsForAdmin`:** `scheduled` 묶음을 추가하고, 각 항목에 공개 방식과 모드를 더한다.
- **새 함수:**
  - `setListed(pollId, listed)`: 언제든 가능하다. 없으면 `not_found`.
  - `reschedule(pollId, { opensAt, deadline })`: 시작 전일 때만 가능하다. 실패 사유는 `not_found` / `started` / `out_of_range`. "지금 바로 시작"은 `opensAt = 지금`이다.
  - `issueCodes(pollId, count)`: 코드를 쓰는 투표이고 시작 전이나 진행 중일 때만 가능하다. 총 500개까지다. 실패 사유는 `not_found` / `codes_disabled` / `closed` / `limit_exceeded`.
  - `resultsCsv(pollId)`: UTF-8 BOM 포함, 투표 정보 줄과 선택지별 줄(선택지, 표 수, 비율, 순위). 투표자 식별 값은 없다.
  - `codesCsv(pollId, baseUrl)`: 코드, 사용 여부, 개인 링크
- **`closePoll`:** 시작 전인 투표는 `not_started`로 거부한다.
- **`extendDeadline`:** 진행 중일 때만(지금과 같음). 시작 전 투표의 시각 변경은 `reschedule`이 맡는다.

### 어댑터

- **공유:**
  - 절대 주소는 `SITE_URL`로 만들고, 없으면 요청 헤더의 호스트를 쓴다.
  - QR은 `qrcode` 라이브러리로 서버에서 SVG를 만든다. 외부 서비스는 쓰지 않는다.
  - 링크 복사는 클라이언트 클립보드 API를 쓴다.
  - 보관된 투표에서는 숨긴다.
- **전체 화면 QR:** 관리자 전용 경로다. 질문, 큰 QR, 짧은 주소, 남은 시간 또는 시작 시각을 보여준다. 서버에서 관리자 세션을 검증한다.
- **CSV 다운로드:** 관리자 전용 Route Handler 두 개(결과, 코드)이다. 첫 줄에서 세션을 검증하고, `Content-Disposition`으로 파일 이름을 지정한다.
- **복제:** 새 투표 폼을 `?from=<id>`로 열고, 서버에서 복제용 설정을 읽어 초기값으로 넘긴다.
- **새 투표 폼:** 시작 예정 시각(선택), 투표 모드, 최대 선택 수, 공개 방식, 참여 코드(켜기 + 개수) 항목을 추가한다.
- **관리자 상세:**
  - 공개 방식 전환
  - 시작 전이면 시작·마감 예정 시각 변경과 "지금 바로 시작". 이때 마감 버튼은 숨긴다.
  - 코드 현황, 추가 발급, 코드 CSV
  - 결과 CSV, 복제, QR 크게 보기
- **투표자 화면:**
  - 시작 전 안내
  - 코드 입력칸(`?code=`로 미리 채움)과 "다른 코드로 투표하기"
  - 복수 선택 체크박스 카드와 선택 수 표시
  - 복수 선택 결과는 선택지별 가로 막대
- **메인과 관리 목록:** "시작 예정" 구역과 "시작 전" 탭, "링크 전용" 뱃지
- **Server Action:** 새 관리자 액션(공개 방식 전환, 시각 변경, 코드 발급)은 모두 첫 줄에서 세션을 검증한다(ADR-0004).
- **문서:** 도움말과 이용약관에 투표자 관점의 설명을 추가한다.
  - 시작 전 투표, 참여 코드 입력, 복수 선택 결과 읽는 법
  - 약관: 참여 코드를 넘겨받아 대신 투표하는 것은 코드를 받은 사람의 책임
  - 관리 기능은 설명하지 않는다.

## Testing Decisions

- **좋은 테스트:** 투표 모듈의 공개 인터페이스만 호출하고, 반환 값과 이후 조회 결과만 본다. 테이블을 직접 조회하거나 SQL을 검사하지 않는다. 시간은 시계 주입으로 움직인다.
- **대상:** 투표 모듈 통합 테스트(`TEST_DATABASE_URL`) 하나. 새 경계는 없다.
- **검증할 동작:**
  - **링크 전용:** 메인 목록에서 빠진다(시작 전, 진행 중, 마감 모두). 투표자 조회로는 보인다. 관리 목록에는 있다. 전환이 즉시 반영된다.
  - **CSV:**
    - BOM, 열 구성, 한글과 쉼표·따옴표가 들어간 선택지의 이스케이프
    - 투표자 식별 값 없음
    - 코드 CSV의 개인 링크
  - **복제용 설정:** 질문, 선택지 순서, 모드, 최대 선택 수, 공개 방식, 코드 사용 여부
  - **시작 전:**
    - 상태 경계: 시작 1초 전은 `scheduled`, 시작 순간은 `open`
    - 표 거부(`not_started`), 투표자 시점에 수치 없음
    - `reschedule` 성공과 실패 사유, "지금 바로 시작"
    - 마감 범위를 시작 시각 기준으로 계산
    - `closePoll` 거부, 메인과 관리 목록의 시작 예정 구역과 정렬
  - **참여 코드:**
    - 발급 개수, 형식, 추가 발급과 상한
    - 코드로 투표 성공
    - 같은 코드 재사용, 없는 코드, 다른 투표의 코드, 코드 누락을 모두 `invalid_code`로 거부
    - 정규화(소문자, 공백)
    - 같은 투표자 ID로도 코드가 다르면 여러 표 가능, 사용 수 집계
    - 코드 없는 투표는 여전히 브라우저당 한 표
  - **복수 선택:**
    - 여러 선택지 저장
    - 0개, 초과, 중복 선택지, 다른 투표의 선택지를 `invalid_choice`로 거부
    - 단일 선택에서 2개 제출 거부
    - 비율이 표 대비(합 100% 초과), 1위와 동점, `myChoices` 여러 개
    - 순위와 격차가 표 대비 %p
  - **마이그레이션 후 기존 동작:** 기존 테스트가 새 인터페이스(선택지 배열, `myChoices`)로 바뀐 것 말고는 그대로 통과한다.
- **선례:** 기존 투표 모듈 통합 테스트와 시계 주입 패턴, 관리자 인증 단위 테스트

## Out of Scope

- 순위 투표, 점수 매기기, 찬반 등 다른 투표 모드
- 참여 코드 폐기·재발급, 코드별 사용자 이름 관리, 코드와 표의 연결
- 인쇄용 개인 QR 카드 묶음 생성 (코드 CSV의 개인 링크로 대신한다)
- 링크 전용을 넘어서는 접근 제한(비밀번호로 보호하는 투표 등)
- 시작·마감 알림(메일, 푸시), 요청 횟수 제한
- 시작한 뒤의 시작 예정 시각 변경, 마감 예정 시각 앞당기기
- 표의 개별 기록(던진 시각 목록)을 담은 CSV
- 관리자 여러 명

## Further Notes

- **3단계는 바꾸는 범위가 가장 넓다.** 표 저장 구조와 `castVote`, 투표자 조회의 모양이 바뀐다. 기존 테스트 대부분이 선택지 배열과 `myChoices`로 바뀌어야 하니, 판정식을 한 곳에 모았던 것처럼 표 저장과 집계도 투표 모듈 안에서 한 번에 바꾼다.
- **코드 추측 방지:** 참여 코드는 요청 횟수 제한 없이 추측을 막아야 하므로 8자리(헷갈리는 글자 제외, 약 32⁸ ≈ 1조 가지)로 만든다. 실패 안내는 한 가지로만 준다(ADR-0007).
- **링크 전용의 한계:** 링크 전용은 접근 제한이 아니다. 투표 ID가 10자 랜덤이라 추측하기 어려울 뿐, 링크를 받은 사람은 누구나 들어온다. 도움말에는 "목록에 나오지 않는 투표도 있다" 정도만 적는다.
- **Next.js 16:** 새 동적 라우트와 Route Handler의 `params`는 Promise다. 구현 전에 `node_modules/next/dist/docs/`의 Route Handler 문서를 확인할 것(AGENTS.md).
- **`bind` 대신 숨은 입력값:** 투표·연장 폼처럼 새 폼에서도 투표 ID는 `bind`로 묶지 말고 숨은 입력값으로 보낸다. JavaScript 없이 제출할 때 멈추는 문제를 피하기 위해서다.
