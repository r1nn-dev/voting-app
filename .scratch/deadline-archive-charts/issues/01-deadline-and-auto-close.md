# 01: 마감 예정 시각과 자동 마감

**What to build:** 관리자는 투표를 만들 때 마감 예정 시각을 반드시 정한다. 입력은 한국 시간 기준이고, 기본값은 24시간 뒤이며, "1시간 / 1일 / 1주" 빠른 선택 버튼이 있다. 투표자는 진행 중인 투표에서 "10월 3일 (금) 오후 6:00 마감 · 3시간 남음"을 보고, 메인 목록에서도 남은 시간을 본다. 마감 예정 시각이 지나면 투표는 자동으로 마감된다. 표는 거부되고, 결과가 공개된다. 관리자는 그 전에 직접 마감할 수도 있다. 마감 시각은 두 경우 중 이른 쪽이다.

사전 정리로, 지금 `closed_at`만 보고 상태를 판단하는 곳을 모두 투표 모듈의 판정식 한 곳으로 모은다. 테스트용 시계 주입도 이 티켓에서 추가한다.

스펙: `.scratch/deadline-archive-charts/spec.md`. 결정 배경: ADR-0006, ADR-0002(갱신), ADR-0005.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 투표 모듈 팩토리가 선택적 시계 `{ now?: () => Date }`를 받는다.
  - 주지 않으면 SQL은 DB `now()`를 쓴다.
  - 주면 그 시각을 SQL 파라미터로 넘긴다.
  - 앱 서버의 `new Date()`로 판정하지 않는다.
- [ ] 판정식을 투표 모듈 한 곳에서만 정의하고, 목록, 투표자 조회, 관리자 조회, 표 삽입, 마감이 모두 이 식을 쓴다. `closed_at`만 보고 상태를 판단하는 코드는 남지 않는다.
  - **마감 여부:** `closed_at`이 있거나 마감 예정 시각이 지금 이하
  - **마감 시각:** `closed_at`과 마감 예정 시각 중 이른 쪽
- [ ] 새 마이그레이션이 `polls.deadline`(timestamptz)을 추가한다.
  - 기존 투표 채우기: 마감된 투표는 `closed_at`, 진행 중인 투표는 마이그레이션 시점 + 7일
  - 채운 뒤 `NOT NULL`로 바꾸고, `deadline` 인덱스를 추가한다.
  - dev/test 브랜치에 적용해도 기존 데이터가 깨지지 않는다.
- [ ] `createPoll`이 `deadline`(절대 시각)을 필수로 받는다.
  - 범위: 지금 + 10분 이상, 지금 + 30일 이하
  - 범위 검사는 삽입 문장 안에서 같은 판정 시각으로 한다.
  - 누락되거나 범위를 벗어나면 필드 오류(`deadline`)를 돌려주고 저장하지 않는다.
- [ ] 투표 만들기 폼:
  - `datetime-local` 입력의 기본값은 KST 기준 지금 + 24시간이다.
  - "1시간 / 1일 / 1주" 버튼은 지금 기준으로 입력칸을 채운다.
  - 제출된 값은 KST(+09:00)로 해석한다.
  - 검증에 실패해도 입력한 내용이 남고, 오류는 마감 예정 시각 입력칸 옆에 한국어로 표시한다.
- [ ] `castVote`의 조건부 INSERT에 "마감 예정 시각 > 지금"을 더한다. 시각이 지난 투표에 투표하면 `closed`를 돌려주고, 화면에는 기존 "이미 마감된 투표" 안내가 보인다.
- [ ] `closePoll`은 이미 마감된 투표(직접 마감이든 시각이 지났든)에 대해 성공을 돌려주고, `closed_at`을 바꾸지 않는다.
- [ ] 투표자 조회가 상태에 따라 시각을 함께 돌려준다: 진행 중이면 마감 예정 시각, 마감이면 마감 시각.
- [ ] 투표자 화면:
  - 진행 중인 투표에 "○월 ○일 (요일) 오전/오후 h:mm 마감 · N 남음"을 표시한다.
  - 메인 목록의 진행 중 투표에 남은 시간을 표시한다.
  - 시각은 `Asia/Seoul` 기준이다. 남은 시간은 가장 큰 단위 하나("3일", "5시간", "20분", "1분 미만")이고, 렌더링 시점에 계산한다.
- [ ] 시드 스크립트의 예시 투표마다 마감 예정 시각을 넣는다. 진행 중인 투표는 몇 시간 뒤부터 며칠 뒤까지 섞고, 마감된 투표는 하나는 직접 마감, 하나는 시각이 지난 것으로 둔다.
- [ ] 통합 테스트는 시계를 주입해서 검증한다:
  - 생성: 마감 예정 시각 누락, 10분 미만, 30일 초과는 오류이고 저장되지 않는다. 경계값(10분, 30일)은 성공한다.
  - 자동 마감: 시각이 지나면 투표자 시점이 `closed`가 되고 결과가 생긴다. `castVote`는 `closed`를 돌려준다. 마감 시각은 마감 예정 시각이다.
  - 직접 마감: 시각 전에 마감하면 마감 시각은 직접 마감한 시각이다. 시각이 지난 뒤 `closePoll`을 불러도 성공하고, 마감 시각은 그대로다.
  - 기존 생성과 목록 테스트를 마감 예정 시각을 넣도록 고친다.
- [ ] `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.
