# 05: 보관과 메인 목록 두 구역

**What to build:** 마감된 투표는 마감 시각으로부터 30일 동안 공개되고, 그 뒤에는 **보관**된다. 보관된 투표는 메인 목록에서 사라진다. 공유 링크로 들어오면 질문과 결과 없이 "공개 기간이 끝난 투표입니다" 안내만 보이고, 관리자로 로그인한 상태면 관리자용 상세 화면으로 가는 링크가 덧붙는다. 관리자는 보관된 투표를 계속 보고 직접 삭제할 수 있으며, 자동 삭제는 없다. 메인 목록은 "진행 중"(마감이 가까운 순)과 "마감된 투표"(마감 시각 최근순) 두 구역으로 나뉘고, 빈 구역에는 "없음" 안내가 있다.

스펙: `.scratch/deadline-archive-charts/spec.md`. 결정 배경: ADR-0006.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 판정식에 보관을 추가한다: 마감이고, 마감 시각 + 30일이 지금 이하. 01의 판정식과 같은 곳에서 정의한다. 보관 여부 컬럼은 추가하지 않는다.
- [ ] 투표자 조회가 `archived` 상태를 돌려준다. 투표 ID와 상태만 담고, 질문, 선택지, 결과는 넣지 않는다.
- [ ] 관리자 조회(`getPollForAdmin`)는 보관된 투표도 `archived` 상태로 모든 내용과 함께 돌려준다.
- [ ] 메인 목록(`listPolls`)이 두 구역을 돌려준다. 보관된 투표는 제외한다.
  - 진행 중: 마감 예정 시각 오름차순
  - 마감: 마감 시각 내림차순
- [ ] 메인 화면은 두 구역을 따로 보여준다. 진행 중에는 남은 시간을 표시하고, 빈 구역에는 "없음" 안내를 보여준다.
- [ ] 공개 투표 페이지:
  - `archived`면 "공개 기간이 끝난 투표입니다"만 보여준다.
  - 관리자 세션이 유효하면 관리자용 상세 화면 링크를 덧붙인다. 링크 표시용 확인일 뿐이고, 상세 화면은 따로 세션을 검증한다.
- [ ] 관리자는 보관된 투표를 기존 삭제 기능으로 지울 수 있다. 기간이 지나도 투표는 자동으로 지워지지 않는다.
- [ ] 시드에 마감 시각이 40일 전인 보관 예시 1개를 추가한다.
- [ ] 통합 테스트는 시계를 주입해서 검증한다:
  - 보관 경계: 마감 시각 + 30일 직전에는 `closed`, 직후에는 `archived`
  - `archived`의 투표자 시점에는 질문과 결과가 없다. 관리자 시점에는 계속 보인다.
  - 메인 목록에서 빠진다.
  - 연장된 투표는 보관 시점도 뒤로 밀린다.
  - 메인 두 구역의 정렬(마감 예정 시각 오름차순 / 마감 시각 내림차순)
- [ ] `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.
