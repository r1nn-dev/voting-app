# 마감 예정 시각, 보관, 결과 그래프

Status: ready-for-agent

## Problem Statement

지금은 관리자가 직접 마감하지 않으면 투표가 영원히 끝나지 않는다. 관리자가 마감을 잊으면 결과가 공개되지 않는다. 투표자는 언제까지 투표할 수 있는지 알 수 없다. 마감된 투표는 관리자가 지우기 전까지 계속 공개된다. 지우면 관리자도 이전 투표의 결과를 다시 볼 수 없다. 관리 화면은 모든 투표를 한 목록에 섞어 보여줘서, 투표가 쌓이면 진행 중인 것과 끝난 것을 구분하기 어렵다. 결과 화면은 선택지를 생성 순서대로 늘어놓은 막대라서, 무엇이 얼마나 차이로 이겼는지나 전체에서 어느 정도 몫인지 한눈에 읽기 어렵다.

## Solution

- **마감 예정 시각:** 모든 투표는 만들 때 마감 예정 시각을 반드시 가진다. 그 시각이 지나면 투표는 자동으로 마감된다.
  - 관리자는 그 전에 직접 마감할 수 있다.
  - 진행 중인 투표는 마감 예정 시각을 늦추는 방향으로만 연장할 수 있다.
  - 투표자는 마감 예정 시각과 남은 시간을 본다.
- **보관:** 마감된 투표는 마감 시각으로부터 30일 동안 공개되고, 그 뒤에는 보관된다. 보관된 투표는 관리자만 본다. 자동 삭제는 없고, 삭제는 관리자가 직접 한다.
- **목록:** 관리 화면은 진행 중 / 마감 / 보관 탭으로 나눈다. 메인 목록은 진행 중과 마감된 투표 두 구역으로 나눈다.
- **그래프:**
  - 투표자는 마감된 투표의 결과를 **비중**으로 본다. 100% 누적 막대 한 줄과 득표순 범례다.
  - 관리자는 새로 생기는 관리자용 투표 상세 화면에서 **순위와 격차**를 본다. 득표순 막대와, 1위와 2위의 차이 요약이다. 마감 전이면 득표 현황으로 본다.

용어는 `CONTEXT.md`를 따른다: 마감 예정 시각, 마감, 마감 시각, 보관, 결과, 득표 현황. 결정 배경은 `docs/adr/0006`과 갱신된 `0002`에 있다.

## Implementation Decisions

### 판정 규칙 (ADR-0006)

- 판정 시각("지금")은 투표 모듈이 SQL 안에서 쓰는 한 값이다. 기본은 DB의 `now()`이고, 모듈에 시계가 주입되면 그 시각을 파라미터로 넘긴다(테스트 전용). 앱 서버의 `new Date()`로 판정하지 않는다.
- **마감 여부:** 관리자가 직접 마감했거나(`closed_at`이 있음) 마감 예정 시각이 지금 이하면 마감이다.
- **마감 시각:** `closed_at`과 마감 예정 시각 중 이른 쪽이다. `closed_at`이 없으면 마감 예정 시각이다.
- **보관 여부:** 마감이고, 마감 시각 + 30일이 지금 이하이면 보관이다.
- 세 식은 투표 모듈 한 곳에서만 정의하고, 모든 조회와 쓰기가 같은 식을 쓴다. 다른 곳에서 `closed_at`만 보고 판단하지 않는다.
- 표시용 "N시간 남음", "보관까지 N일"은 렌더링 시점에 계산한다. 이건 판정이 아니므로 모듈이 돌려준 시각과 서버 시각으로 계산해도 된다.

### 모듈 변경

**투표 모듈:** 기존 모듈을 확장한다. 새 모듈은 만들지 않는다.

- **팩토리:** 선택적 옵션 `{ now?: () => Date }`를 받는다. 주지 않으면 DB `now()`를 쓴다.

- **`createPoll({ question, options[], deadline })`**
  - `deadline`은 절대 시각이다. 폼 어댑터가 KST 입력을 절대 시각으로 바꿔 넘긴다.
  - 필수이고, 범위는 지금 + 10분 이상, 지금 + 30일 이하다.
  - 범위 검사는 삽입 문장 안에서 같은 판정 시각으로 한다. 조건을 만족하지 않으면 행이 만들어지지 않고, 필드 오류(`deadline`)를 돌려준다.
  - 기존 필드 오류(질문, 선택지)는 지금처럼 앱 코드에서 먼저 검증한다.

- **`extendDeadline(pollId, newDeadline)`**
  - 성공하거나, 반환 값으로 실패 사유를 돌려준다: `not_found` / `closed` / `not_later`(현재 마감 예정 시각 이하) / `out_of_range`(지금 + 30일 초과).
  - 한 문장 조건부 UPDATE로 처리한다. 조건: 진행 중이고, 새 시각이 현재 마감 예정 시각보다 늦고, 새 시각이 지금 + 30일 이하.
  - 0행이면 원인을 판별해 사유로 바꾼다.
  - 마감과 연장이 동시에 들어와도 마감된 투표는 다시 열리지 않는다.

- **`closePoll(pollId)`:** `closed_at`을 채운다. 이미 마감됐다면(직접 마감이든 마감 예정 시각이 지났든) 성공으로 보고, `closed_at`은 바꾸지 않는다.
  - 마감 예정 시각이 이미 지난 투표를 나중에 "마감"해도 마감 시각은 앞당겨지지 않는다. 마감 시각은 둘 중 이른 쪽이기 때문이다.

- **`castVote`:** 삽입 조건에 "마감 예정 시각 > 지금"을 더한다(ADR-0005의 조건부 INSERT 확장). 실패 사유는 지금과 같고, 시각이 지난 경우도 `closed`다.

- **`getPollForVoter(pollId, voterId)`:** 상태 세 가지를 판별 가능한 유니온으로 돌려준다.
  - `open`: 질문, 선택지(생성 순서), 내 선택, 마감 예정 시각. 수치 필드는 없다.
  - `closed`: 질문, 내 선택, 마감 시각, 결과(비중).
    - 결과: 선택지별 표 수, 비율(소수점 첫째 자리), 1위 여부, 내 선택 여부, 총 표 수
    - 정렬: 득표 내림차순, 동점이면 생성 순서
  - `archived`: 투표 ID와 상태만. 질문, 선택지, 결과는 넣지 않는다.
  - 없으면 "없음"이다.

- **`getPollForAdmin(pollId)` (신규):** 상태와 관계없이 다음을 돌려준다.
  - 질문, 상태(`open` / `closed` / `archived`), 마감 예정 시각, 마감 시각(마감이면)
  - 순위와 격차:
    - 선택지를 득표순으로 정렬하고, 순위를 붙인다(경쟁 순위: 동점은 같은 순위, 다음 순위는 건너뜀). 각 선택지에 표 수, 비율, 1위 여부를 붙인다.
    - 요약:
      - 총 표 수
      - 1위 선택지들: 동점이면 여럿
      - 동점 여부
      - 1위와 2위의 차이: 표 수와 %p. %p는 반올림 전 비율로 계산한 뒤 소수점 첫째 자리로 반올림한다. 1위가 동점이면 0이다.
      - 선택지가 모두 0표면 1위와 격차는 "없음"이다.
  - 없으면 "없음"이다.

- **`listPolls()` (메인, 변경):** 두 구역을 돌려준다.
  - 진행 중: 마감 예정 시각 오름차순. 각 항목은 ID, 질문, 마감 예정 시각.
  - 마감: 마감 시각 내림차순. 각 항목은 ID, 질문, 마감 시각.
  - 보관된 투표는 제외한다.

- **`listPollsForAdmin()` (변경):** `open` / `closed` / `archived` 세 묶음과 각 개수를 돌려준다.
  - 정렬은 메인과 같고, 보관은 마감 시각 내림차순이다.
  - 각 항목: ID, 질문, 마감 예정 시각, 마감 시각, 총 표 수, 1위 선택지(동점이면 여럿, 0표면 없음)
  - 탭 선택은 화면이 하고, 모듈은 세 묶음을 모두 돌려준다. 수백 개 규모라 한 번에 읽어도 된다.

- **순수 함수(모듈 내부):**
  - 비중 계산과 정렬
  - 순위와 격차 계산(경쟁 순위, 동점, %p)
  - 기존 비율과 1위 판정은 재사용한다.

**얇은 어댑터**

- **투표 만들기 폼:**
  - 날짜/시간 입력(`datetime-local`)에 기본값 "지금 + 24시간"을 KST로 채운다.
  - 빠른 선택 버튼 "1시간 / 1일 / 1주"는 지금 기준으로 채운다.
  - 제출된 값은 KST(+09:00)로 해석해 절대 시각으로 바꾼다.

- **관리자용 투표 상세 화면(신규):** 순위와 격차 그래프, 요약, 마감 예정 시각과 남은 시간, 공개 페이지 링크를 보여준다.
  - 연장 영역: 진행 중일 때만 보인다. 입력칸, "+1시간 / +1일 / +1주" 버튼(현재 마감 예정 시각 기준), 확인 단계, 실패 사유 안내
  - 마감 버튼: 진행 중일 때만 보인다. 기존 확인 단계를 쓴다.
  - 삭제 버튼: 기존 확인 단계를 쓴다.

- **Server Action:**
  - 연장 액션이 새로 생긴다. 첫 줄에서 관리자 세션을 검증한다(ADR-0004).
  - 성공한 변경 뒤에는 기존 헬퍼로 메인, 관리 목록, 공개 페이지를 갱신하고, 관리자 상세 화면도 함께 갱신한다.

- **공개 투표 페이지:**
  - `archived`면 "공개 기간이 끝난 투표입니다" 안내만 보여준다.
  - 관리자로 로그인한 상태면 관리자용 상세 화면 링크를 덧붙인다.

- **시각 표시:**
  - 모든 날짜는 `Asia/Seoul`로 표시한다. 예: "10월 3일 (금) 오후 6:00"
  - 남은 시간은 가장 큰 단위 하나로 표시한다: "3일", "5시간", "20분", "1분 미만"

- **그래프:** 라이브러리 없이 HTML/CSS로 그리는 서버 컴포넌트다.
  - 비중 막대: 조각 너비 = 비율, 선택지별 고정 색 팔레트(최대 10색), 범례에 글자 수치
  - 순위 막대: 가로 막대, 1위 강조
  - 색만으로 정보를 전달하지 않도록, 범례와 막대 옆에 비율과 표 수를 항상 글자로 적는다.

### 스키마

- 새 마이그레이션에서 `polls`에 `deadline timestamptz`를 추가한다.
- 채우기: 마감된 투표(`closed_at` 있음)는 `closed_at`, 진행 중인 투표는 마이그레이션 시점 + 7일
- 채운 뒤 `NOT NULL`로 바꾼다.
- 진행 중 정렬을 위해 `polls(deadline)` 인덱스를 추가한다.
- 상태나 보관 여부 컬럼은 추가하지 않는다. 모두 조회할 때 계산한다(ADR-0006).
- `closed_at`의 뜻은 "관리자가 직접 마감한 시각"으로 좁혀진다(ADR-0002 갱신).

### 무결성

- 표 삽입: 진행 중(직접 마감 안 됨, 마감 예정 시각 > 지금)일 때만 행이 만들어지는 한 문장으로 한다.
- 생성: 마감 예정 시각 범위 검사를 삽입 문장 안에 둔다.
- 연장: 진행 중이고, 새 시각이 현재보다 늦고, 30일 이하일 때만 갱신되는 한 문장으로 한다.
- 마감: 이미 마감됐으면 `closed_at`을 바꾸지 않는다.

## Testing Decisions

- **좋은 테스트:** 투표 모듈의 공개 인터페이스만 호출하고, 반환 값과 이후 조회 결과만 확인한다. DB에 직접 시각을 써 넣거나 SQL과 내부 함수를 검사하지 않는다.
- **시간 이동:** 테스트는 모듈에 시계를 주입해 시간을 앞으로 돌린다. 예: 마감 예정 시각을 1시간 뒤로 만든 뒤, 2시간 뒤 시계로 다시 조회한다. 시계를 바꾼 모듈 인스턴스를 새로 만들어도 같은 DB를 본다.
- **테스트 대상:** 기존 경계인 투표 모듈 통합 테스트(`TEST_DATABASE_URL`) 하나. 관리자 인증 모듈 테스트는 변경 없음. 새 경계는 없다.
- **검증할 동작:**
  - 생성:
    - 마감 예정 시각 누락, 10분 미만, 30일 초과는 필드 오류이고 저장되지 않는다.
    - 경계값(10분, 30일)은 성공한다.
  - 자동 마감:
    - 마감 예정 시각이 지나면 투표자 시점에 `closed`가 되고, 결과가 생긴다.
    - `castVote`는 `closed`를 돌려준다.
    - 마감 시각은 마감 예정 시각이다.
  - 직접 마감:
    - 마감 예정 시각 전에 마감하면 마감 시각은 직접 마감한 시각이다.
    - 마감 예정 시각이 지난 뒤 `closePoll`을 불러도 성공하고, 마감 시각은 그대로다.
  - 연장:
    - 성공하면 투표자 시점의 마감 예정 시각이 바뀐다.
    - 원래 마감 예정 시각이 지난 뒤에도 연장된 시각 전이면 투표할 수 있다.
    - `not_later`, `out_of_range`, `closed`(직접 마감 / 시각 지남), `not_found`
  - 보관:
    - 마감 시각 + 30일 직전에는 `closed`, 직후에는 `archived`다.
    - `archived`의 투표자 시점에는 질문과 결과가 없다.
    - 관리자 시점에서는 계속 보인다.
    - 메인 목록에서 빠지고, 관리 목록의 `archived` 묶음에 들어간다.
    - 연장된 투표는 보관 시점도 뒤로 밀린다.
  - 목록:
    - 메인 두 구역의 정렬(마감 예정 시각 오름차순 / 마감 시각 내림차순)
    - 관리 세 묶음의 정렬과 개수
  - 결과(비중):
    - 득표 내림차순, 동점이면 생성 순서
    - 비율 합계와 반올림, 1위 강조(동점 포함), 내 선택 표시, 0표
  - 순위와 격차:
    - 경쟁 순위(동점 1, 1, 3)
    - 1위와 2위 차이(표, %p)
    - 1위 동점이면 차이 0과 동점 표시
    - 0표면 1위와 격차 없음
    - 마감 전에도 관리자 시점에는 있다.
    - 투표자 시점 `open`에는 여전히 수치가 없다.
- **기존 테스트:** 생성과 목록 테스트는 마감 예정 시각을 넣도록 고친다. 결과 순서 테스트는 "생성 순서"에서 "득표순"으로 바꾼다.
- **선례:** 투표 모듈 통합 테스트, 관리자 인증 모듈의 가짜 시계 테스트 패턴

- 원형/도넛 차트, 차트 라이브러리

- 목록 페이지네이션, 검색

## Further Notes

- 이 작업은 ADR-0002를 일부 대체한다. `closed_at IS NULL`이 더 이상 "진행 중"을 뜻하지 않는다. 기존 코드에서 `closed_at`만 보고 상태를 판단하는 곳(목록, 투표 삽입, 마감, 투표자와 관리자 조회)을 모두 새 판정식으로 바꿔야 한다. 하나라도 남으면 시각이 지난 투표가 계속 표를 받는다.
- 판정은 DB 시각 하나를 기준으로 한다. 서버 렌더링 때 계산하는 "N시간 남음"은 표시용이라, 몇 초 어긋나도 판정에는 영향이 없다.
- 결과 순서를 생성 순서에서 득표순으로 바꾸는 것은 이전 MVP 스펙의 결정을 뒤집는 것이다. 이번 대화에서 합의했다.
- 공개 투표 페이지에서 쿠키로 관리자 여부를 확인하는 것은 링크 표시용이다. 관리자용 상세 화면 자체는 기존대로 서버에서 세션을 검증한다.
- Next.js 16 관련: 새 동적 라우트의 `params`는 Promise다. 탭은 `searchParams`(Promise)로 읽는다. 구현 전에 `node_modules/next/dist/docs/`의 관련 문서를 확인할 것(AGENTS.md).
