# 복수 선택의 표는 한 장에 선택지 여러 개를 담고, 비율은 표 대비로 센다

투표 모드에 복수 선택을 더하면서 **표**의 뜻을 "한 투표자가 한 번 제출한 선택(선택지 1개 이상)"으로 넓혔다. 한 사람이 선택지마다 따로 표를 던지는 모델도 가능하지만, 그러면 "한 투표에 한 표"라는 규칙과 표 수의 의미(몇 명이 투표했나)가 깨진다. 그래서 표는 여전히 한 장이고, 그 안에 선택지가 여러 개 들어간다. 결과의 비율은 **그 선택지를 고른 표 수 ÷ 전체 표 수**로 센다. "투표한 사람의 60%가 김밥을 골랐다"가 복수 선택에서 알고 싶은 값이기 때문이다. 그래서 비율의 합은 100%를 넘을 수 있다. 전체 선택 수 대비로 세면 합이 100%가 되지만, 사람 수와 관계없는 숫자가 된다.

## Consequences

- 한 표를 "표 한 행 + 고른 선택지 여러 행"으로 저장한다. 한 장만 던질 수 있다는 보장은 지금처럼 표 행의 제약(ADR-0005)이 맡고, 선택지 행들은 같은 문장 안에서 함께 들어간다. 그래서 선택지 일부만 저장된 표는 생기지 않는다.
- 최대 선택 수, 선택지 개수 0개 금지, 다른 투표의 선택지 금지는 저장하는 문장 안에서 검사한다. 앱 코드의 검증은 안내 문구용이다.
- 지금 투표자 결과 화면의 비중 막대는 합이 100%라는 전제로 그려서 복수 선택에 맞지 않는다. 복수 선택의 결과는 선택지별 가로 막대(표 대비 %)로 보여준다. 관리자의 순위와 격차는 그대로 쓰고, 격차는 표 대비 %p로 센다.
- 단일 선택은 "선택지를 정확히 하나 담은 표"로 같은 구조에 들어간다. 모드마다 저장 구조를 따로 두지 않는다.
- 순위 투표는 이번에 넣지 않았다. 넣게 되면 집계 방식(보르다 점수, 결선 투표 등)을 먼저 정하고 이 ADR을 다시 본다.
