# 참여 코드는 1회용이고, 어떤 코드로 어떤 표를 던졌는지 남기지 않는다

브라우저당 한 표(ADR-0001)는 시크릿 창이나 쿠키 삭제로 우회할 수 있다. 그래서 공정성이 중요한 투표를 위해 투표마다 **참여 코드** 사용 여부를 정할 수 있게 했다. 코드를 쓰는 투표는 관리자가 1회용 코드를 발급해 한 사람에게 하나씩 나눠 주고, 코드 하나로 표를 한 번만 던질 수 있다. 코드를 쓰지 않는 투표는 지금처럼 브라우저당 한 표다. 투표 공통 코드 하나(입장 비밀번호)도 검토했지만, 코드를 아는 사람이 브라우저를 바꿔 여러 번 투표하는 것을 막지 못해 택하지 않았다.

## Consequences

- 코드 투표에는 브라우저당 한 표 제한을 두지 않는다. 코드가 이미 한 사람당 한 표를 보장하고, 교실 태블릿 한 대로 여러 사람이 각자의 코드로 투표하는 경우를 막지 않기 위해서다. "내 선택" 표시는 그 브라우저에서 마지막으로 던진 표를 기준으로 한다.
- 코드는 "사용됨"으로만 표시하고, 표는 코드 없이 따로 저장한다. 관리자가 누구에게 어떤 코드를 줬는지 알더라도 그 사람의 선택은 알 수 없다. 약관의 "누구인지 알아내는 데 쓰지 않는다"와 맞추기 위한 결정이다.
- 코드의 사용 처리와 표 저장은 한 SQL 문장(CTE)으로 한다. 사용되지 않은 코드일 때만 사용 처리하고, 그 결과가 있을 때만 표를 넣는다. 같은 코드로 동시에 두 번 제출해도 표는 하나만 들어가고(ADR-0005의 원칙), 코드만 소모되고 표가 빠지는 일도 없다.
- Vercel에는 요청 횟수 제한 수단이 없어서, 추측으로 맞히지 못하도록 코드를 충분히 길게(8자리, 헷갈리는 글자 제외) 만든다. 틀린 코드, 이미 쓴 코드, 다른 투표의 코드는 모두 같은 안내("사용할 수 없는 코드입니다")로 돌려준다. 어느 쪽인지 알려주면 추측에 단서가 되기 때문이다.
- 코드를 넘겨받은 사람이 대신 투표하는 것은 막지 못한다. 코드를 받은 사람의 책임으로 보고 약관에 적는다.
