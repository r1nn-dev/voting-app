# 투표 무결성은 앱 코드가 아니라 DB 제약으로 보장한다

"한 브라우저당 한 표", "다른 투표의 선택지에는 표를 넣을 수 없음", "마감된 투표는 표를 받지 않음"을 앱 코드에서 먼저 조회하고 검사하면, 동시에 들어온 요청 사이에 경쟁 조건이 생긴다. 그래서 세 규칙을 모두 DB 수준에서 강제한다.

- `votes`의 PK는 `(poll_id, voter_id)`다. 같은 브라우저의 두 번째 표는 거부된다.
- `votes(poll_id, option_id)`는 `options(poll_id, id)`를 참조하는 복합 FK다. 다른 투표의 선택지에 표를 넣을 수 없다.
- 표 삽입은 `INSERT ... SELECT ... FROM polls WHERE id = $1 AND closed_at IS NULL` 한 문장으로 한다. 마감 직전에 들어온 요청도 원자적으로 처리된다.
- 선택지와 표는 `ON DELETE CASCADE`로 투표 삭제를 따라간다.

앱 코드의 검증(순수 함수, Vitest로 테스트)은 사용자에게 보여줄 오류 메시지를 만드는 용도다. 최종 보장은 DB가 한다. 이 제약들은 통합 테스트(Neon `test` 브랜치)로 검증한다.
