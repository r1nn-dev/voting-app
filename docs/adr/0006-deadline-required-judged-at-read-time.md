# 마감 예정 시각은 필수이고, 자동 마감과 보관은 조회할 때 판정한다

끝나지 않는 투표를 없애기 위해 모든 투표는 만들 때 마감 예정 시각(`polls.deadline`, NOT NULL)을 가진다. 범위는 지금부터 10분~30일이고, 관리자는 진행 중인 투표를 같은 범위 안에서 늦추는 방향으로만 연장할 수 있다. 자동 마감과 보관(마감 시각 + 30일)은 크론 작업으로 `closed_at`을 채우지 않고, 쿼리가 실행되는 시점의 `now()`와 비교해서 판정한다. Vercel Cron은 설정이 더 필요하고, Hobby 플랜에서는 하루 한 번만 돌아서 마감이 늦게 반영된다. 반면 조회 시점 판정은 시각이 지나는 순간 바로 마감되고, 표 삽입 조건(ADR-0005)에 `deadline > now()`를 더하면 DB가 원자적으로 막는다.

## Consequences

- `closed_at`이 NULL이어도 마감된 투표가 있다. `closed_at`은 "관리자가 직접 마감한 시각"이다. "마감됐는가"는 `closed_at IS NOT NULL OR deadline <= now()`로 판정하고, 마감 시각은 `least(closed_at, deadline)`이다. 두 식은 투표 모듈 한 곳에만 두고, 다른 곳에서 `closed_at`만 보고 판단하지 않는다.
- 보관 여부도 저장하지 않고 `마감 시각 + 30일 <= now()`로 계산한다. 그래서 관리자가 직접 보관하거나 보관을 되돌릴 수 없다. 필요해지면 그때 컬럼을 추가한다.
- 연장은 `UPDATE ... SET deadline = $new WHERE <진행 중> AND $new > deadline` 한 문장으로 한다. 마감과 연장이 동시에 들어와도, 마감된 투표가 연장으로 다시 열리지 않는다(ADR-0002).
- 판정 기준은 DB의 `now()` 하나다. 앱 서버 시계와 섞어 쓰지 않는다. 테스트만 투표 모듈에 시계를 주입할 수 있고, 그러면 그 시각이 `now()` 대신 SQL 파라미터로 들어간다. 운영 코드는 시계를 주입하지 않는다.
